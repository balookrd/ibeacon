# iBeacon Broadcaster

Android-приложение, которое непрерывно транслирует один iBeacon с заданными
UUID / major / minor и старается пережить системные «убиватели» фоновых
процессов.

Интерфейс выполнен в современном дизайне **Material 3 (Material You)** с поддержкой
динамических цветов Android 12+, Hero-карточкой статуса с анимированным пульсирующим
радаром активности, сегментированными кнопками управления параметрами радиосигнала
и интерактивным чек-листом живучести службы.

## Сборка

Нужен JDK 17+ (подойдёт тот, что внутри Android Studio) и Android SDK 35.

```bash
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

Тесты:

```bash
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew test
```

Release (подписанный, с R8 и урезанием ресурсов):

```bash
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew assembleRelease
```

APK: `app/build/outputs/apk/release/app-release.apk` (~1,2 МБ)

Установка на подключённое устройство:

```bash
~/Library/Android/sdk/platform-tools/adb install -r app/build/outputs/apk/release/app-release.apk
```

### Подпись

Ключ лежит в `keystore/release.jks`, пароли — в `keystore.properties`; оба файла
в `.gitignore` и в репозиторий не попадают. **Их нельзя терять**: обновление уже
установленного приложения возможно только тем же ключом.

Чтобы подписывать своим ключом, замените `keystore.properties`:

```properties
storeFile=путь/к/своему.jks
storePassword=…
keyAlias=…
keyPassword=…
```

Если файла нет, release соберётся неподписанным. Debug- и release-сборки
подписаны разными ключами, поэтому поверх одной другую не поставить — сначала
`adb uninstall com.balookrd.ibeacon`.

## Как пользоваться

1. Задать Proximity UUID, major, minor и measured power (RSSI на 1 метре,
   обычно −59 — по нему приёмник оценивает расстояние).
2. Выбрать периодичность: `~1000 мс`, `~250 мс` или `~100 мс`. Это три пресета
   Android (`ADVERTISE_MODE_LOW_POWER / BALANCED / LOW_LATENCY`) — произвольное
   значение в миллисекундах система задать не позволяет.
3. Выбрать мощность передатчика (влияет на дальность, не на частоту).
4. Пройти чек-лист «Живучесть» — каждый пункт открывает нужный системный экран.
5. Нажать «Старт». Пока маяк вещает, в шторке висит постоянное уведомление;
   остановить можно оттуда или кнопкой «Стоп».

Изменения параметров во время работы применяются кнопкой «Применить».

## Как приложение держится в живых

- foreground service типа `connectedDevice` с постоянным уведомлением;
- `START_STICKY` и перезапуск по `onTaskRemoved` (свайп из недавних);
- partial WakeLock, пока идёт трансляция;
- два независимых сторожа: точный будильник (~5 мин, пробивает Doze) и
  периодический WorkManager (15 мин, переживает перезагрузку);
- собственный self-check раз в 30 секунд — стек умеет ронять рекламу молча;
- автозапуск после перезагрузки (`BOOT_COMPLETED`, `LOCKED_BOOT_COMPLETED`) и
  после обновления приложения (`MY_PACKAGE_REPLACED`);
- слежение за состоянием Bluetooth: после выключения и включения BT маяк
  поднимается сам;
- настройки в device-protected storage, чтобы восстановление работало до
  разблокировки экрана.

## Ограничения

- **Эмулятор не годится для проверки эфира.** Проверять реальную трансляцию
  нужно на физическом устройстве сканером (nRF Connect, Beacon Scope и т. п.).
- Часть устройств не поддерживает режим BLE-периферии — приложение это
  определяет и пишет об этом прямо на экране.
- «Принудительная остановка» из настроек Android отключает все будильники и
  задания приложения: после неё маяк поднимется только ручным запуском. Это
  поведение системы, обойти его без root нельзя.
- На MIUI / EMUI / ColorOS автозапуск нужно включить вручную — API для этого
  нет, приложение лишь открывает нужный экран настроек.
